# File-size tier implementation evidence

The user selected complete-document editing with existing CodeMirror viewport rendering, automatic IEC file sizes, and configurable policies at the existing 1 MiB provider threshold and new 10/100 MiB viewer tiers. The 10 MiB policy defaults automation, browser draft writes and differences off once; the 100 MiB policy requires stronger inline confirmation. These choices do not establish measured editor limits. This supersedes the 2,097,152-character advisory configuration and removes that field from active source and documentation.

Inspection found that automatic update off still left content polling active. Large/huge documents now detach the source watch while both automation choices are off, preserving small-document watching and restoring the necessary watch when either choice is enabled. Exact source/save metadata supplies classification. A stale restored descriptor cannot override a fresh file size. Tier entry clears pending draft and automation timers before asynchronous source hashing; the accepted watch result retains its document/source/read-generation guard after detachment.

The shared provider added an optional existing-content byte ceiling and exact read/save byte metadata in commit `1106060dc118a93ffa18e2374012c17cdd132148`. Viewer requires its independent ^0.1.1 release. The existing installation planner rejects an older selected provider; a focused real planner fixture proves rejection before mutation and acceptance of 0.1.1. No equal-version check or parallel runtime capability protocol was introduced. Already-local save growth remains unprompted; reading unseen huge source content requires the stronger action.
