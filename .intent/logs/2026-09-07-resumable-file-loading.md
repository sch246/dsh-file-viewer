# Resumable file loading and idle large-edit checks

The user reports that a roughly 30 MiB file progressively slowed and disconnected with `Remote stream WebSocket closed`; a complete HTTP retry also failed with `ERR_INCOMPLETE_CHUNKED_ENCODING`. These observations establish interrupted large transfers, not a proven rendering leak. The user requested concurrent downloads, positional black segments, a progressively readable prefix and retention of completed parts after Stop or Retry. They explicitly accepted in-page-only resume; closing or refreshing the page may restart.

The viewer replaces filesystem WebSocket and full-text download callers with the provider 0.1.5 prepare/chunk/finish API. The generic document owner retains one source read handle and one canonical prefix. The filesystem handle retains decoder state and bounded out-of-order raw chunks. Manual delta fallback also uses this transport and retains Local while staging Source. The provider's completion remains responsible for an actual stable whole-file canonical hash and revision; the browser independently verifies that final hash.

The user also reports lag while editing the actual large file and approved delaying large-document complete checks until input is idle for about 300 ms, while preserving immediate text ownership and exact save verification. This supersedes any inference from a prior smaller, approximately 5,000-line document about large-file typing costs. The viewer delays hash invocation and UTF-8 encoding, admits one background local check, and retains only the latest pending edit. No CodeMirror transaction or text-publication delay is introduced.

The user's later variable edit-block and per-block cached-hash proposal remains a separate investigation. Fixed raw download chunks do not define editable blocks, and no block tree, Merkle digest or replacement for canonical SHA-256 is implemented here.

Candidate dependencies were installed with `DSH_USER_FILES=/root/dsh-resumable-load/user-files/packages/dsh-user-files DSH_SIDEBAR=/root/dsh-decoupling-apply/sidebar/packages/dsh-right-sidebar pnpm run install:local`. The selected provider commit is `da725df559c37fb3773810eb49b61096d0400e95`. `DSH_CHECKOUT=/root/deepseek-harness pnpm run build` passes. A focused nine-file Vitest run passes 85 tests covering transport, document lifecycle, confirmation and red interruption UI, positional ranges, delta save/update, browser wiring and idle edit checks. `pnpm run test:setup` passes all three installer checks, including rejection of provider 0.1.4. Initial build attempts exposed TypeScript optional-property and option-forwarding errors, corrected before the passing build. A broader focused regression run exposed a generic watch re-registration and missing post-save Local hash; both are corrected and the final run passes.

No active profile, Host source, service, deployment or remote branch was changed by this implementation. Live HTTP and browser acceptance belong to the parent integration step. Complete-document editor, final encoding/hash and provider final reads still incur whole-file costs; in-page resume does not guarantee bounded total editor memory.
