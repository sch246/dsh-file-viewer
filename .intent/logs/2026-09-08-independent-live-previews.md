# Independent live preview plugins

The user requested live Markdown preview beside an editor, unchanged scroll offsets except a necessary clamp after content shrink, and an HTML-rendering toggle with a separate default. The user then explicitly chose independent Markdown and HTML plugins at the same level. Both installable packages remain in this repository's packages workspace with separate versions and optional Bundle membership; neither depends on the other, manager or Links.

The existing viewer already shares Local across text handlers. Markdown moves its rendering, locale and styles out of viewer and retains the `markdown` handler id for restored views. Its presentation owns per-view scroll and HTML state; a browser-local default, following the text view's line-number-default precedent, initializes only newly created presentations. There is no new content polling or filesystem reader. Resize/layout handling retains numeric offsets and clamps shorter content. Both previews expose Edit side by side through the public viewer opening API.

The HTML plugin consumes only complete Local text and displays it in a sandboxed opaque-origin iframe. Script permission starts off, can be changed per view, and has an independent new-view default. Only allow-scripts is added when enabled; no same-origin, popup, form or top-navigation permission is granted. Text edits and explicit Reload recreate iframe runtime. A fixed about:blank base prevents relative project URLs from resolving against Harness; this delivery is not a project web server.

Viewer owns sources/documents/layout integration and now requires no Markdown renderer dependencies. Independent preview packages own their dependencies and registration lifetimes. Deferred Client injection avoids blocking the transport before resourceWorkbench becomes ready; Host entries do not import browser code. The core shared-text-view fixture no longer imports the removed built-in Markdown factory.

Owned Client/package compilation and bundles completed. No automated tests, browser automation or visual acceptance ran, per the user's instructions. Installation used the existing dsh plugin transaction to add both explicit package paths, followed by manifest/Bundle/lockfile/resolution checks. Activation and exact local evidence are recorded under /root/.local/state/dsh-maintenance/2026-09-08-independent-previews/. A pnpm peer report identifies pre-existing better-model-provider peer declarations, unrelated to either new preview.
