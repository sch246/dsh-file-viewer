# Sidebar host consumer

`ResourceViewHost`, `ResourceNavigation` and occurrence callbacks live in the consumer-owned `host.ts`. Public resource options, the resource service face and body props no longer import external sidebar types. `sidebar-host.ts` maps the installed provider to those requirements; startup retains its seat registration. The workbench continues to own documents, source/handler selection and resource state, with no layout or navigation-history store.

The selected 0.1.6 Host's official sidebar already owns docking, tab kinds and body/title/guide seats. Its public API currently lacks asynchronous close vetoes with committed removal notification, preview/pin behavior, opaque restoration checkpoints and content-navigation history. The synchronous close hook and occurrence abort signal cannot substitute for those obligations: body disposal and Session changes must not discard drafts, and a cancelled navigation must not create a replacement tab. The official Host enhancement precedes adapter cutover and removal of the external dependency. This commit is consumer isolation, not the completed official migration.

The host interface names the required return values and sequencing: one cancellable request from link resolution through commit; source-Session-bound group lookup; preview replacement after close guards; checkpoint changes without history or focus changes; restored readiness before missing/title publication; and state release after exact-occurrence removal. History stores descriptors, not document buffers. STATE retains the user behavior and shared-document requirements.
