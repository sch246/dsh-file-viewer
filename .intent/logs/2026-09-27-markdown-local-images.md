# Document-relative Markdown images

The sidebar Markdown preview dropped every non-HTTP(S) image source. `content.tsx` passed `previewUrl` as react-markdown's `urlTransform`, which returns undefined for a local `src`; react-markdown assigns that undefined result to the URL attribute, so the `<img>` reached the DOM without `src`. A minimal render of `![figure](images/figures/x.png)` produced `<img alt="figure"/>` while the HTTP(S) source survived. Treating the relative path as a page-relative URL would only have produced a 404.

The fix adds `readLinkedBytes(viewId, href, signal)` to the frozen `ResourceWorkbenchClientService`. It resolves the href through the containing view's source `resolveLink`, reads the resolved destination's bytes under the same view byte lifetime, and returns them with the resolved descriptor merged in so the media type survives. The Markdown preview admits a local `src` for `img` through `previewUrl` and its image component loads the bytes, creates an object URL, and revokes it on unmount. Each image starts loading only as it nears the viewport through one `IntersectionObserver`; a failed or cancelled read keeps the alt text. `..` stays governed by the existing source link resolution, which normalizes paths without a workspace jail exactly as source-authored links already do.

The change is on `/root/worktrees/dsh-file-viewer-local-images` (branch `codex/markdown-local-images`, based on `51ecd61`), with `DSH_CHECKOUT=/root/deepseek-harness`. The worktree has no installed dependencies, so the probe reused prepared package tooling and a worktree-local resolution override for the changed viewer package; the live profile, service and `/root/.dsh` files were never changed.

Verification: the reproduction; viewer and Markdown-preview typecheck and build; the new `packages/dsh-file-viewer/tests/linked-bytes.client.spec.ts` (two tests, covering document-relative resolution through the containing view and the unavailable-capability rejection); and a temporary jsdom render check that observed `images/figures/x.png` passed to the loader, a `blob:` image source, and revoke on unmount. A private-Home probe at `/tmp/dsh-probe-mdimg` (candidate links, copied module fallbacks, live settings and credentials referenced only by path) booted the profile and `verify-web.mjs` reported 67 boot entries, both candidate bundles exactly once and loadable, and zero problems; four unrelated host plugins failed to import in that probe.

Browser acceptance must still open the real `数学错题汇总.md` in the live right pane and observe its 243 relative images with no page or console errors. The probe had no Session, so its sidebar never mounted and the end-to-end image interaction remains unobserved.
