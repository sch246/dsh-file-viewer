# File viewer installation and adaptation map

Use this document as the installation prompt: establish the selected environment, adapt the supplied implementation to its public capabilities, and deliver the product behavior below. Refine the map from user feedback and observed Host behavior; source symbols and package placement are adaptation references, not frozen interface choices. Record installation observations, implementation debt and validation results in the local logs for [dependency ownership](../logs/2026-09-06-independent-feature-dependencies.md), [file-size policies](../logs/2026-09-07-file-size-tiers.md), [progressive loading](../logs/2026-09-07-progressive-text-loading.md), and [incremental saves](../logs/2026-09-07-incremental-saves.md).

## Intent

Provide a Session-aware generic resource workbench in the DeepSeek Harness Web right sidebar. Client plugins contribute sources and lazy handlers without receiving workbench, document or group store mutation authority.

## Installation map

### Required capabilities and ownership

| Feature | Required capabilities | Ownership and optional cooperation |
| --- | --- | --- |
| Sidebar | Harness layout APIs | Layout, groups, tabs, previews, persistence and instance lifecycle only; no filesystem or feature-opening policy. |
| Viewer | Sidebar and the shared authenticated UI filesystem provider | Owns the `filesystem` source, supported-file opening, text/image handlers, shared documents and drafts. Requires neither manager nor Links. The editor stays an internal plain dependency, not a separately chosen user feature. |
| Manager | Sidebar and the same shared provider | Owns the tree, directory opening, navigation and mutations. Requires neither viewer nor Links; file clicks use the common Host opening entry. |
| Shared filesystem package | Authenticated Harness UI/Remote APIs | Neutral service definition, one Node provider and generated Remote declarations; Session-relative resolution, metadata, text/bytes and revision-guarded saves. Build and distribute it independently of feature packages. An independent package in the manager repository is one possible location, not a required repository arrangement or a dependency on the manager feature. |
| Optional Links toggle in the shared package | Shared filesystem access and Host text-link/opening APIs | Recognizes and confirms paths in Markdown inline code. Requires no sidebar, viewer or manager. Its toggle controls path decoration only; filesystem access and original session-file links remain available when disabled. |

Authenticated user filesystem operations retain service-process permissions, independently of agent `ctx.fs`, sandbox and approval. The shared provider owns path resolution and one canonical-resource publication queue for text and byte saves, including revision checks; viewer documents own browser synchronization, not disk publication. Viewer owns the `filesystem` source and `resourcePollIntervalMs`; manager owns `directoryPollIntervalMs`, tree state and mutations.

All file clicks, including Chat links and manager rows, use the Host's common opening entry, represented by `chat/open-workspace-file` in the supplied sources. Viewer handles supported files and manager handles directories. Unhandled requests delegate to the native opener on the service-process machine; errors after a handler takes responsibility propagate without native fallback. Preserve preview, pin and open-to-the-right intent without exposing viewer internals to other features.

### Adapt and install in the selected environment

1. Select explicit `DSH_CHECKOUT`, `DSH_HOME` and `DSH_PROFILE`. Read the selected Host's instructions, profile composition, manifests, actual resolution targets and existing adaptation receipts. Preserve unrelated plugins, user configuration, sidebar layout and browser drafts. Use the requested feature combination to select dependencies; cooperation with another feature is not permission to require its installation.
2. Compare the selected Host's actual authenticated Remote, Session path metadata, Client module/slot registration, sidebar lifecycle and common opening APIs with the supplied [manifest](../../packages/dsh-file-viewer/package.json), [Bundle](../../packages/dsh-file-viewer/cordis.patch.yml), [workbench](../../packages/dsh-file-viewer/src/client/workbench.ts), [document service](../../packages/dsh-file-viewer/src/client/service.ts) and [editor package](../../packages/dsh-file-viewer-editor/package.json). Adapt names and interfaces to the supported Host while preserving the behavior below. Use one opening chain and one filesystem provider, not parallel compatibility implementations. Existing equivalent Host capabilities need no duplicate patch; attribute each necessary adaptation before applying it and retain changes owned by other plugins.
3. Inspect the Host's declaration and Remote generators, including external-project support such as Typert `externalProjectReferences`, and its source-launch requirements. Read the [repository build guide](../../README.md#build-and-install) and actual scripts before choosing commands. Build the selected Host declarations/generator, then the provider and feature Host/Remote/Client artifacts as their dependency graph requires. Use explicitly selected repository tools and compatible APIs; a historical package version or sibling checkout path is not an environmental requirement.
4. Resolve one independently distributed shared provider for all selected consumers. Declare compatible peer/API ranges and development dependencies; keep package versions independent without equal-version checks. Reuse a provider satisfying all consumer ranges, report incompatible ranges explicitly, and avoid duplicate provider rows or Remote namespaces. Viewer/editor form one user feature; manager and Links remain independent options. Before registry distribution, use the repository’s explicit `install:local` route with selected package directories or tarballs; it installs without a lockfile and never tracks tarballs. Once compatible dependencies are published, normal `pnpm install` generates a fresh lockfile. Local path overrides do not require neighbouring repositories for normal builds.
5. Read [setup](../../scripts/setup-host.sh) and [uninstall](../../scripts/uninstall-host.sh) before execution and verify their actual dependencies, flags, scope and effects against this map. Treat them as tools to adapt, not authorities that can turn a historical prerequisite into a feature requirement. Install the selected feature and needed shared artifacts through the Host's supported plugin transaction, preserving complete configuration rows and effective settings. Keep resource polling under viewer and directory polling under manager; preserve Links enablement and explicit external-opening preferences when adapting an existing profile.
6. Before enabling huge-text editing in a deployment, inspect the reverse proxy’s request-body limits and Harness `client-connection.maxRequestBodyBytes`. JSON escaping, range hashes and metadata can make patch uploads larger than replacement text; select compatible limits for the actual patchText route and Host. Whole-file edits can still produce large patches. Raised limits and user-chosen tiers do not establish browser memory capacity, localStorage capacity or universal file-size reliability. Inspect manifest, lockfile, exact installed package targets, Bundle membership, generated Remote declarations and Client rows after the transaction. Cold-start an isolated profile with the selected feature combination before activating a user's profile. Exercise the behavior and failure conditions below; a successful package build or script inspection alone does not establish a working installation. Setup must not restart services implicitly.
7. Remove only the selected feature's owned contributions and dependencies. Retain sidebar and the shared provider while other consumers need them; check remaining consumer manifests before removing shared capabilities. Inspect residual resolutions, rows and generated browser entries. Do not delete user files, browser preferences or drafts, and do not reverse an entire historical Host patch merely because one feature is removed.

### Combination checks

With sidebar and the shared provider, viewer alone must read and edit supported remote files reached through original session-file links; manager alone must browse and mutate directories and send unhandled file clicks to the native opener. With both features, files reach viewer and directories reach manager independent of installation order. Links works without either feature or sidebar; disabling it stops automatic path decoration and discovery queries while retaining filesystem access and original session links. Handler failures remain visible without fallback, and removal of one consumer leaves the others usable.

## Product behavior

- The frozen `ctx.resourceWorkbench` face exclusively owns source and handler registrations, handler selection, associations, resource views and shared text documents.
- A resource identity contains a Session id, source id and source-owned resource id. Descriptors add a name and optional MIME, kind, size and location without replacing that identity.
- A source independently contributes optional text and byte reading, guarded writing, watching and external opening. Text is never inferred by decoding arbitrary bytes. Duplicate live source ids fail.
- Handler selection applies an explicit request, user association, unique highest-priority default and safe text fallback in that order. Equal defaults expose a choice. Handler modules load only after their view mounts.
- The persistent workbench bar contains source breadcrumbs and a right-aligned handler dropdown. Each handler row has independent name and toggleable default targets: the name switches the current handler through its existing guards; the default marker sets or cancels its association without switching the current handler. External opening remains available inside the dropdown when supported.
- The built-in image handler consumes real bytes through an inert image element. SVG defaults to image and remains available through the text handler via open-with.
- Exact text references share one Base/Local/Source document across multiple view ids. Each view separately retains selection, scroll and undo state; moving or remounting a view does not reread or copy the document.
- Manual Update observes the latest source while preserving local edits. Filesystem manual Save uploads ordered disjoint original-Base line ranges, mandatory SHA-256 hashes of exact canonical old ranges and replacement text. All ranges validate against one current disk snapshot; unrelated changes outside them survive. Insertions guard neighboring content, with an explicit empty-file case. Mismatches, overlaps and out-of-bounds ranges conflict without partial publication or a bulk fallback. Preserve exact untouched BOM/EOL bytes and terminal newlines; recheck the server snapshot immediately before atomic rename. Generic manual Save uses its source’s conditional writes; a writable source without conditional writes requires explicit overwrite confirmation. Automatic Update requires watching; automatic Save requires conditional writes. Each shared document owns independent concrete automatic update/save choices.
- Delta save results return actual canonical SHA-256, size and revision without a full-text response. Equal captured-Local hashes advance Base/Source while retaining later edits. A differing hash means own changes saved alongside other source changes: advance virtual Base to captured Local, retain current Local, retain the previously verified Source text/hash pair marked stale, without pairing old text with the new actual hash or inventing Source from Local, show saved-with-other-changes, pause automation and keep lastSyncedAt unchanged. Further manual deltas remain allowed against this Base; refresh is needed for actual Source comparison, not as a mandatory prerequisite for another guarded save. Explicit overwrite remains confirmed and builds guarded ranges from known Source.
- Global defaults initialize new documents, with optional source defaults taking precedence. Changes never mutate existing document choices or reschedule their automation, including during loading, refresh, source reconnect and Session switching. Hover or focus each current automation checkbox to expose its separate default checkbox immediately to the left. Defaults share an independent observable subscription. There are no separate default-setting buttons, inheritance or reset actions. Closing the last view and reopening uses the latest defaults.
- Confirmed resource absence retains views, local text and editor state, pauses text automation and marks tab titles with a strikethrough. Sources own absence reports; renderer availability and unrelated failures do not imply existence. A missing source file during cold restoration still exposes a valid retained Base/Local draft without an invented Source or revision. Successful reads or watch snapshots clear absence and allow synchronization to resume. Sources may use `ResourceMissingError` or the generic missing watch event; the filesystem adapter maps `user-files/not-found`.
- Exact hashes classify synchronized, local-ahead, source-ahead, diverged and unknown states. A conflict retains Base, Local and Source text, pauses automation and offers confirmed Overwrite source or Discard local actions.
- The text editor's upper-right overlay always shows the synchronization relationship, with state-dependent color. Its status also shows each actual update and save activity independently, including simultaneous operations. Activity text cycles through zero to three dots in fixed-width suffixes; reduced-motion mode uses static text, and assistive technology ignores the dots. Activities come exclusively from the existing read/save controllers and never infer a saved result from source observation or a synchronized hash relationship. Initial loading remains a separate state.
- When automatic update is off, permanent status additionally displays elapsed time since an actual successful load, pull or equal-hash save. The timestamp belongs to the shared runtime document and is not persisted across restoration. Local edits, request starts, observed-but-unpulled Source, metadata polls, failed saves and successful patches leaving other changes do not reset it. Locale-owned seconds, minutes, hours with minutes and floored days retain the dirty/conflict/missing status. Use cheap timers with page-visibility, disabled-label and unmount cleanup.
- Hover, keyboard focus or touch/click on the status exposes a vertical Update, Save, Line numbers, Browser draft and Differences stack. It remains expanded after mouse leave; Escape, an outside click or selecting the status dismisses it. Update and Save have current automation checkboxes. Line numbers has a current checkbox and a button that performs the same toggle, plus a hover/focus-revealed default checkbox. Touch keeps default checkboxes reachable. Operations do not reveal action buttons. Only controls intercept editor pointer input; failures, pauses and conflict-resolution actions remain independently available.
- Differences becomes Back to editor and uses the same local EditorView, preserving undo, selection and scroll across mode changes. Local remains editable according to source capability, while Source is always read-only. Shared Base-aligned row slots determine both panes' paired Base/current line-number columns, deleted rows, padding and linked vertical scroll geometry. Extra rows on any side shift later rows in every visible pane. Soft wrapping preserves original line numbers and uses common visual row heights. Baseline deletions are red and nonselectable; inserted lines are pale green with darker changed-fragment backgrounds rather than underline marks. Deleted rows and padding never enter document selection, clipboard text or writes. Unchanged sides are omitted, identical sides appear once, and synchronization retains comparison mode with current text except for the one-time large-tier reset. The lazy editor package reuses the maintained diff algorithm and owns alignment, not independent per-pane alignment decisions.
- Each text resource view retains line-number visibility, expanded controls, comparison mode and opaque editor state in its existing handler-state owner. The persisted browser default initializes only new presentation state; changing it leaves current views untouched.
- Preserve complete-document editing and CodeMirror viewport rendering. Display exact source file size in automatic 1024-based units (bytes, KiB, MiB, GiB). Viewer Config supplies positive safe-integer `largeFileBytes` and `hugeFileBytes` with huge strictly above large, defaulting to 10 MiB and 100 MiB. On the first entry above the large tier in an open document, default automatic update/save and browser draft writes off, and reset each view to ordinary editing with differences off once. Every choice remains manually enableable and later observations never reset it again. While both automation choices are off in a large or huge document, stop content polling; manual Update and revision-guarded Save remain available. Show one permanent orange tier mark with tooltip and accessible explanation. These are user-chosen policies, not measured editor limits. Hashing every edit, exact text, history and guarded publication remain unchanged; classify size from source/confirmation/save metadata without encoding the whole text on every keystroke.
- Browser-local draft records retain exact Base and Local text and the document's automation choices under the complete document identity. Restoration freshly loads Source and recomputes all three hashes with the one-time large-tier defaults applied when needed; version-1 drafts without automation initialize it from current defaults. Provider revisions and transient failures remain runtime-only. A sidebar-committed close removes the record, while Client disposal flushes pending retention only when draft writing is enabled. The shared document’s Browser draft toggle stops future writes without deleting existing records or local edits; enabled retention remains subject to browser storage capacity and does not guarantee recovery of huge files.
- The right-sidebar workbench owns groups, tabs, preview replacement, pin state, activation and close gestures. The viewer registers one static `resource-workbench` renderer. First edit pins a preview; close and handler switch honor document and handler vetoes. Close confirmation does not release a view or document; cleanup runs only after the sidebar commits removal of that exact instance.
- Optional source locations remain opaque. A location can display a label and segments; a selectable source location invokes the source callback with its JSON-safe selection hint, while a selector id launches a registered right-sidebar feature. Filesystem breadcrumb callbacks use the common Host opening helper.
- `@dsh-external/dsh-file-viewer-editor` owns CodeMirror dependencies and editor construction. Source state updates reuse the mounted view, preserve bounded cursor positions and do not enter undo history.
- Viewer registers its own filesystem source backed by the shared authenticated provider. Manager independently owns directory navigation and its Files launcher. Optional Links owns automatic Chat path recognition; all use the common Host opening entry.
- Filesystem text above the shared provider’s configured threshold (1 MiB by default) requires an explicit Load file button click before content reading, hashing, editor creation, watch polling or new draft serialization. Show the actual byte size in automatically scaled IEC units in a neutral panel. Above hugeFileBytes, show a stronger inline memory/unresponsiveness message and Continue loading. Lower approval carries a provider-enforced byte ceiling, so later unseen growth past the huge tier requires its own action; huge approval removes that ceiling for the open document. This is browser-content loading, not a separate download endpoint. Approval belongs to one open shared document, applies to subsequent reads, watches and saves, and is forgotten after its last view closes or browser restoration. A loaded source growing beyond the threshold pauses further reads and synchronization, retains the current editor and local text, and offers the same action. Already-local edits can exceed the threshold and save without a new output-size prompt; reading an existing large source in a later operation still requires approval. Pending initial confirmation preserves existing draft records. Confirmed text has no additional size cap; byte reads remain separately bounded.
- Approved initial filesystem loads use sequential streaming Remotes. Show the first text segment immediately and coalesce later appends with positive `progressiveFlushIntervalMs` (300 ms by default). A solid black square-ended 3 px line at the breadcrumb/text divider shows byte progress and fades at completion. Partial text remains selectable, copyable and read-only; no partial hashes, draft writes, comparisons, automation or saves are permitted. Stop and failures retain the incomplete preview with a Retry loading action; retry starts from the beginning. Complete source validation and hashing enable editing and restore retained drafts. Append and read-only transactions preserve the same editor, selection and scroll. Refreshes retain Local while staging complete observations, and filesystem saves upload guarded changed line ranges.
- Bytes remain exact; text rejects malformed UTF-8 and NUL, normalizes loaded line endings to LF, and retains EOL metadata in an opaque revision. Saves restore the loaded EOL convention, including mixed existing-line endings, and the terminal-newline presence represented by editor text. Revisions contain exact content hashes and file stat values; one shared-provider queue serializes text and byte publication, stages in the same directory and rechecks the server’s expected snapshot immediately before atomic rename. Delta saves do not compare the whole disk to a client’s old revision; whole-text and byte APIs retain revision checks for their callers. Guarded optimistic saves cannot provide strict compare-and-swap against an uncooperative external writer between that recheck and rename. Source watches run only while subscribed, await read and consumer processing before scheduling another, and abort timers/requests on disposal.

- Filesystem background updates transfer only SHA-256-guarded original-coordinate line deltas against the browser's known Source hash. Viewer `maxDeltaBytes` defaults to 1 MiB of actual serialized UTF-8 success-envelope bytes, capped also by provider policy. The provider retains bounded canonical baselines established by validated reads, completed streams and saves, using configurable `baselineBytes` (256 MiB of accounted canonical string data) and `baselineEntries` (16); accounting is not total process heap. It uses stat identity for unchanged files and a bounded maintained differ for changes. Full current-file reads and linear tokenization can still consume Host resources; changes preserving all observed stat fields are not detected by the metadata shortcut. Provider `deltaConcurrency` defaults to one background computation; busy callers retry without a queue. Manual requests bypass background admission.
- All browser filesystem watches share one execution permit covering reads, range/hash verification and awaited consumer application. Busy subscriptions skip and reschedule. The next delay is at least the observed whole-cycle work duration and the applicable idle interval: ordinary `resourcePollIntervalMs` (2000 ms in the Bundle), `largeResourcePollIntervalMs` (10,000 ms above largeFileBytes), or `hugeResourcePollIntervalMs` (30,000 ms above hugeFileBytes). Failures and provider busy responses use exponential backoff capped by `resourcePollBackoffMaxMs` (60,000 ms). Validate positive ordered timing values; manual actions remain outside the background permit. Generic watch callback promises propagate through the workbench; generic invalidations retain their source model.
- Missing or over-budget baselines, transfer size excess and exhausted diff budgets preserve Local, stop repeated expensive automatic work and show a manual Update action. Automatic updates never silently fetch complete content. Explicit Update first requests a delta from a known verified Source pair, then may fall back to a complete read under existing size confirmation if a delta is unavailable. Successful refresh reattaches a stopped watch. A transient missing/failure state recovers from unchanged verified metadata without a full-text response.
- Received deltas validate all range hashes before application and verify the final canonical Source hash once. With automatic update off, advance observed Source only and retain Local and synchronization age. With automatic update on and a common Base, apply matching remote ranges to Local while preserving unrelated local edits; advance Base to Source and retain remaining dirty changes. Overlap, line shifts or incompatible Base pause automatic reconciliation without changing Local. No fuzzy relocation is permitted. Apply validated editor ranges as transactions that map selection/history and retain scroll; no remote undo entry or per-range draft serialization is introduced. Integrity failures do not advance Source or synchronization age.

## Constraints

- The right-sidebar package owns group layout, previews, tabs and restoration descriptors. This package uses only its public service and `rightbar.view` slot.
- Each source defines canonical text. The generic editor does not trim, normalize line endings or synthesize a terminal newline.
- Source and handler contributors use public generic resource types; manager file-opening requests use the common Host entry without importing viewer internals.

## Non-goals

- Owning filesystem authorization, directory operations or automatic Chat path recognition.
- Native HTML execution, archive editing, collaborative editing or random-access file windows.
- Persisting browser editor buffers in the Session log or sending them to the model.
- Restarting, publishing or asserting acceptance of a live deployment from repository setup.
