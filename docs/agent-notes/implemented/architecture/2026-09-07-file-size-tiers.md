# Exact-byte file-size policies

The document service classifies exact source bytes from read, confirmation and save metadata. Viewer Config owns ordered large and huge tiers; the provider owns its ordinary text-load threshold and enforces the caller's optional `maxConfirmedBytes` before reading existing content. A lower approval carries the huge-tier ceiling, while an explicit huge-file action removes that ceiling for the open document. Viewer requires user-files ^0.1.1, and the installation planner rejects an incompatible provider before profile mutation.

The first large-tier observation disables document automation and future browser draft writes before asynchronous source hashing, and resets each retained view's differences mode once. Manual controls remain available. Existing drafts and in-memory edits are preserved while retention is off; enabled browser retention remains limited by storage capacity. Large documents stop content polling while both automation choices are off, and resume it when either is enabled. An accepted watch snapshot can finish hashing after its size observation detaches the watch, provided its document, source registration and read generation still match.

File size and the permanent status advisory use the byte tiers. No separate character-count policy, per-edit byte encoding, delayed hashing, alternative transfer protocol or editor feature cap is needed. Complete-file loading and JSON saves remain subject to browser memory and deployment request-body limits. Focused document/panel, Config and installation tests cover confirmation, tier entry, manual reenablement, draft retention, polling, metadata precedence and incompatible-provider rejection.
