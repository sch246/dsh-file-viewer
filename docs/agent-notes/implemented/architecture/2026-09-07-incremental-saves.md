# Guarded line saves and synchronization age

The generic document service distinguishes whole-text conditional save from `saveTextDelta`. Delta sources receive captured Base and Local in process and report the actual canonical published hash. The filesystem source uses the shared user-files pure line differ to form original-coordinate line ranges, expands pure insertions with neighboring content, hashes exact old ranges and sends only ranges to `patchText`. Empty original files have an explicit zero-line insertion case. No whole-text fallback follows a conflict.

The provider validates every range against one current disk snapshot, preserves unrelated source bytes, and rechecks its own snapshot before atomic publication. The client’s old whole revision is not a delta-save prerequisite. Matching result hashes advance Base and Source normally while retaining edits made during the request. Differing hashes advance only the saved Base, retain current Local, retain the last verified Source pair marked stale and pause automation with an explicit saved-with-other-changes notice. Further manual deltas compare against that saved Base; explicit overwrite requires known Source and uses the same guarded path.

`lastSyncedAt` belongs to the runtime document and changes on an actual load, pull or equal-hash save. Edits, failed/no-op saves, ordinary observations and successful delta saves leaving other changes do not reset it. A localized elapsed label accompanies the relationship status while automatic update is off; its timer follows display precision and stops for hidden pages, disabled labels and unmounts.

The production filesystem source no longer calls the bulk text-save Remote. Generic whole-text providers retain their declared save method, and the shared provider retains its bulk API for independently installed earlier viewer consumers. Delta update ownership and the current API requirement are described in [adaptive polling and delta updates](2026-09-07-adaptive-polling.md).
