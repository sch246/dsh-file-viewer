# Progressive and resumable text loading

The document service owns the provisional read-only text, contiguous byte count and append coalescing. A source may supply a one-shot generic stream or a retained `createTextRead` handle. The shared document retains that handle across failed attempts and view remounts; the handle owns decoding and out-of-order transport buffers, while the document owns the accumulated canonical prefix. Existing ready documents stage a separate Source observation without appending to Local.

Filesystem reads use the shared provider's prepared unary chunk protocol. A bounded worker pool downloads and hashes raw chunks, with lookahead limited to twice its concurrency beyond the contiguous prefix. The browser decodes each contiguous raw chunk once with a fatal incremental UTF-8 decoder; incomplete multibyte characters, BOM and split CRLF sequences retain their meaning. Completed raw buffers are released after decoding. Fixed byte offsets identify transport ranges, not editable text blocks.

Retry validates the prepared version, path, size and chunk size before reusing cached content. Changed plans fail visibly and reset transport state for the next explicit attempt while retaining the provisional preview. Transient request failures receive bounded retries; caller cancellation and semantic or integrity failures do not. Every attempt aborts and awaits outstanding requests before another attempt uses its retained state. Last close and source disposal abort requests and release buffers. Resume is memory-only.

The first nonempty segment publishes immediately; later text updates coalesce at the configured interval. Received ranges update the positional progress line independently of text publication. Only stable Host completion plus browser verification of the complete canonical SHA-256 establish a usable revision. Partial text has no Base and cannot enter edits, saves, comparisons, automation or draft writes. The same transport stages complete manual refreshes when a delta is unavailable.

The editor handle appends at the document end without an undo entry and reconfigures read-only permission through a CodeMirror Compartment. Both retain the same view, selection and scroll. Final coalesced text can append in the same render that enables editing. Progress receipt never grants document completeness.

Large Local edits publish immediately with an unknown hash, then schedule full-text checks after the configured idle delay. One background local check runs at a time; only the latest pending generation remains. Save cancels its duplicate idle check and verifies captured current text immediately, reusing an identical running check when available. Small documents keep immediate checks. This bounds repeated whole-text work during typing without changing the canonical SHA-256 or making the editor's text asynchronous.
